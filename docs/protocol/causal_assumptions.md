# 因果假设与威胁登记表

**版本：0.1.0**  
**状态：Protocol v0.1 工程试点基线**

本文件记录 GoalEvo Track A 进行因果解释时必须成立的假设。它的目的不是宣称假设必然正确，而是使反证条件透明。

## A01 干预纯度

除治理机制开关外，各方法使用相同基础模型、初始 Harness、工具、任务、时间预算和修改机会。

**威胁**：治理组拥有更多 token、更强工具或更丰富提示。  
**控制**：统一运行器；预算字段强制记录；方法差异清单自动 diff。

## A02 Oracle 独立性

真实结果由固定 Oracle 按 `G_t^*` 判断，不使用被测系统的 Evaluator 作为主要真值。

**威胁**：系统修改评价器后同时提高“真实分数”。  
**控制**：Oracle 代码和版本由独立路径维护；执行日志记录两套判定。

## A03 隐藏目标可发现性

每项隐藏条款都存在预先冻结的可识别证据；系统不需要无依据猜测研究者意图。

**威胁**：Benchmark 实际测量读心或偶然猜中。  
**控制**：每项条款维护 discoverability map 和最小充分证据。

## A04 授权真值明确

每个规范变化事件的角色、权限、签名和有效时间可由程序确定。

**威胁**：对“谁有权”存在研究者事后解释。  
**控制**：Authority Graph 在实验前冻结；反事实双胞胎只改变授权身份。

## A05 目标与评价器可分离

Goal Contract 表达规范要求，Evaluator 只实现测量，不得把当前 Evaluator 等同于目标本身。

**威胁**：Evaluator 的 bug 被错误解释为 Goal 缺陷。  
**控制**：保存 `D_G` 与 `D_E` 的独立测试集。

## A06 无隐藏泄漏

Experimental Agent 不得访问 `G_t^*`、Gold 标签、密封测试或其他方法结果。

**威胁**：提示词、日志、文件名或异常信息泄漏。  
**控制**：可见性字段、文件隔离、访问日志和 canary 测试。

## A07 版本完整性

所有任务结果必须唯一关联 Snapshot；所有生效 Patch 必须有审批和验证记录。

**威胁**：运行时配置与已记录版本不同。  
**控制**：内容哈希、不可变 Snapshot、启动前 manifest 校验。

## A08 失败不被选择性删除

方法失败、超预算和非法 Patch 仍属于方法结果，除非符合预注册的基础设施失败规则。

**威胁**：只重跑不利于某方法的失败。  
**控制**：失败分类、重跑计数和原始日志保留。

## A09 任务抽样不依赖结果

训练、验证、Replay、ID、OOD 和 Sealed 划分在主实验前冻结。

**威胁**：看到结果后更换测试任务。  
**控制**：Split Manifest 哈希和独立保管。

## A10 严重风险不能被汇总分抵消

硬约束和严重 False Pass 使用独立安全终点，不并入可被普通成功补偿的总分。

**威胁**：大量低风险成功掩盖少量高影响失败。  
**控制**：层级结论规则和安全 Gate。

## A11 观测到的适应不是简单记忆

H3 的恢复应在未见但同规则结构的任务上测量，而不是只复测触发修改的案例。

**威胁**：系统只打补丁。  
**控制**：反事实、组合泛化、Replay 和 OOD。

## A12 人类决定不由主结果诱导

确认性假设、非劣界限、排除规则和严重错误定义在查看主实验结果前冻结。

**威胁**：事后选择有利阈值。  
**控制**：Decision Record、Freeze Manifest、访问时间戳。

## A13 安全不通过无限弃权获得

方法不能通过把困难任务全部交给人，制造“零错误”的表面安全。

**威胁**：安全率提高仅来自覆盖率崩塌，或系统对本可正确处理的任务频繁错误弃权。  
**控制**：分别报告 Coverage、Abstention Precision、Erroneous Abstention Rate 和 Selective Risk；错误弃权是独立失败模式，不被隐藏在平均效用中。
