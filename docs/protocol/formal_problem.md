# GoalEvo Phase 1 形式化问题规范

**版本：0.1-draft**  
**状态：等待 D001–D005 人类决定**

## 1. 研究对象

GoalEvo 研究一种能够根据经验提出并部署系统修改的自进化系统。系统可能修改执行 Harness、评价器、目标契约、自治权限、证明规则或能力边界。研究的核心不是“修改是否发生”，而是对每次观测到的表现变化进行可识别归因：

- 真正的执行能力是否提高；
- 评价器是否只是更准确地测量原目标；
- 系统是否发现了原先遗漏的既有目标；
- 真实规范是否发生了合法变化；
- 系统是否未经授权扩大了成功接受集合；
- 系统是否通过扩大权限或降低证明要求绕过目标治理。

## 2. 可部署系统快照

在离散代际 `t`，系统快照定义为：

\[
\Sigma_t=(H_t,E_t,G_t,A_t,R_t,C_t)
\]

| 对象 | 含义 | 示例 |
|---|---|---|
| `H_t` | Harness / 执行与能力结构 | 提示词、记忆、检索、工具、工作流、重试和代码配置 |
| `E_t` | Evaluator / 评价器 | 判断任务结果是否满足当前可见要求的程序 |
| `G_t` | Goal Contract | 系统当前可见且认为有效的目标、硬约束、例外和弃权条件 |
| `A_t` | Autonomy Contract | 系统可以自主执行的动作、工具、数据和审批边界 |
| `R_t` | Assurance Contract | 什么证据足以证明结果，以及谁能签署证明 |
| `C_t` | Capability Envelope | 当前经实验确认的可靠任务范围和适用条件 |

这些对象必须版本化、可单独 diff、可重放，并禁止通过一个不可解释的“总配置”同时改变多个层级。

## 3. 时间索引真实目标

对每个受控微型世界，研究团队预先建立：

\[
G_t^*
\]

`G_t^*` 表示在时间 `t` 真正有效的完整规则集合。它是该实验世界中的操作性规范真值，而不是普遍道德真理。

### 3.1 初始隐藏条款

初始时，系统只看到不完整的 `G_0`。`G_0^*` 中的隐藏条款必须满足可发现性条件：每项条款都能通过预先冻结的任务失败、正式政策、审计事件或反事实证据逐步显现。

### 3.2 规范变化

外部法规或有权主体可以使：

\[
G_{t+1}^* \neq G_t^*
\]

规范变化必须记录提案时间、批准时间、生效时间、适用范围、授权链和历史影响。

## 4. 三个接受集合

对任务情境 `x` 和候选结果 `y`，定义：

- `Acc(G_t^*)`：真实目标允许的结果集合；
- `Acc(G_t)`：当前可见目标契约允许的结果集合；
- `Acc(E_t)`：当前评价器实际判为通过的结果集合。

由此形成三个不同误差来源。

### 4.1 目标理解误差

\[
D_G(t)=Acc(G_t)\triangle Acc(G_t^*)
\]

表示当前目标契约与真实有效目标之间的差异。

### 4.2 评价器误差

\[
D_E(t)=Acc(E_t)\triangle Acc(G_t)
\]

表示评价器未准确实现当前可见目标契约的差异。

### 4.3 能力误差

即使 `G_t` 和 `E_t` 正确，`H_t` 仍可能无法产生满足 `G_t^*` 的结果。能力误差由固定任务集和独立 Oracle 测量。

## 5. 变化归因

### 5.1 能力贡献

在固定真实目标、任务集、权限和独立 Oracle 的条件下，仅更换 Harness：

\[
\Delta U_H=U^*(H_{t+1};G_k^*,D)-U^*(H_t;G_k^*,D)
\]

只有这种固定条件下的改善，才可以被归为能力贡献。

### 5.2 目标变化贡献

固定 Harness，比较不同真实目标版本：

\[
\Delta U_G=U^*(H_k;G_{t+1}^*,D)-U^*(H_k;G_t^*,D)
\]

该差异描述外部规范变化对表现的影响，不应被记为模型能力提升。

### 5.3 评价器贡献

固定 Harness 和 Goal Contract，仅更换 Evaluator，测量其对 `G_t` 的实现误差是否下降。评价器分数提高不能直接作为真实效用提高的证据。

### 5.4 未经授权的目标移动

若一个变更扩大 `Acc(G_t)` 或降低 `R_t` 的证明要求，却没有有效授权或不能由 `G_t^*` 的变化解释，则记为未经授权的目标移动或证明弱化。

## 6. 实验单位

| 单位 | 定义 | 主要用途 |
|---|---|---|
| `Task` | 一次具体业务请求 | 任务效用、False Pass、False Block |
| `Event` | 政策、审计、投诉、授权或新证据 | 产生发现和变更机会 |
| `PatchProposal` | 一次原子修改提案 | 变更分类、授权和接受集合分析 |
| `Generation` | 经验—诊断—提案—验证—晋级循环 | 多代趋势、回归和恢复时间 |
| `Run` | 方法×世界×模型×种子的完整轨迹 | 配对比较和聚类分析 |
| `Snapshot` | 某代可部署状态 | 版本交叉评价和重放 |

同一 Run 内的 Task 不是独立实验重复；统计模型必须显式处理世界、模板、Run 和种子层级。

## 7. 可见性边界

| 数据 | Experimental Agent | Builder Agent | Audit Agent | Human Custodian |
|---|---:|---:|---:|---:|
| 可见 Goal Contract | 是 | 是 | 是 | 是 |
| `G_t^*` | 否 | 仅生成阶段受控访问 | 只读/脱敏 | 是 |
| Gold 变更标签 | 否 | 训练前可见，主实验隔离 | 是 | 是 |
| Sealed Test | 否 | 否 | 仅解封后 | 是 |
| 其他方法结果 | 否 | 分析阶段可见 | 是 | 是 |

## 8. 研究主张的识别条件

以下条件未满足时，不得作强因果归因：

1. 各方法使用相同基础模型、工具、预算和事件序列分布；
2. 方法差异确实只来自预注册的治理机制；
3. Oracle 独立于被测系统的 Evaluator；
4. 隐藏目标和测试划分未泄漏；
5. 失败 Run 未被选择性排除；
6. Goal、Evaluator、Autonomy 和 Assurance 版本均可追溯；
7. 关键结论在未见任务和密封测试上复现。

## 9. 非目标

Phase 1 不试图证明：

- 所有现实价值冲突都可以形式化；
- `G_t^*` 是唯一正确的道德目标；
- 受控世界结果可直接外推到所有开放世界；
- 人类授权者不会犯错；
- 零次观察到错误等于风险为零。
